# 核心玩法循环

## 概述

游戏采用 TRPG 叙事循环：AI 描述场景 -> 玩家声明行动 -> AI 判定结果 -> 必要时触发前端 D100 检定 -> AI 继续叙事。当前实现围绕单浏览器本地多人（hot-seat）体验。

## 主循环流程

```
AI 叙事
  -> 玩家输入行动
  -> runDmTurn()
  -> Narrator JSON + 工具调用
    ├─ 格式无效：修复重试一次；仍无效则拦截为系统错误
    ├─ Director / StateResolver：校验工具并生成事件
    ├─ 前台：applyAiResponse() 立即更新状态与叙事
    ├─ 有检定：收集同轮独立检定 -> 逐项 prepareCheck()/掷骰 -> 汇总全部结果回传 AI
    └─ 后台：summary / facts / System2 / episodic memory / case board 按回合落地
```

## 页面状态机

```
title
  ├─ 开始游戏 -> setup -> game
  ├─ 继续游戏 -> game
  └─ AI 设置 -> title modal
```

## 队伍行动

1. 所有调查员始终共享同一个 `currentScene`，不存在逐人位置状态。
2. 前端按 `currentActorIndex` 逐人收集行动并组合为“本轮行动宣言”。
3. 最后一名调查员完成声明后，AI 一次性结算完整队伍回合。
4. 任一合法场景变更都会同步移动全队，并统一更新章节、背景、在场 NPC 与 AI 上下文。
5. 若 AI 判断本轮声明互相矛盾，首次冲突要求玩家重新输入本轮行动；再次冲突请求前端 `幸运` 检定仲裁。

## 技能检定

检定数值来自 `src/data/gameRules.ts`，`dice.ts` 只执行这些规则，不再单独持有难度倍率或大失败阈值。

一轮可以包含多项检定。规则层按玩家行动顺序建立队列：不同玩家的独立调查、同轮多次攻击、同一玩家使用不同技能处理不同目标，都可以分别结算；同一玩家用同一技能检查一组相关目标时合并为一次检定，避免无意义的掷骰膨胀。队列结束前不接受新行动，最后统一把原始声明与全部骰果交给 AI 续写。

每项检定在掷骰前都带有结果契约：作者检定只能触发 YAML 定义的事件和效果；自由检定只能改变局部局面，但成功必须产生可复用收益，失败必须带来代价或继续路径。因此不会再出现“要求掷骰，却没有任何可结算结果”的孤儿检定。

点击掷骰即锁定前端唯一结果。弹窗使用美术交付的古铜面板和透明旋转帧图，全部文字统一为字魂云雀宋；背景黑色 40%、模糊 4px。2.5 秒后揭晓总点数和对应骰面数字（100 为 `00 + 0`），不显示「十位／个位」文字。结果区只显示一个完整等级，如「大失败」，停留至玩家确认。多人队列显示当前项次；减少动态效果或动画资源加载失败时保留静态骰面，仍能正常揭晓和确认。素材来源及处理说明见 [骰子资源](../../assets/ui/dice/README.md)。

| 难度 | 目标值 |
|------|--------|
| 普通 | 技能值 |
| 困难 | 技能值 / 2 |
| 极难 | 技能值 / 5 |

| 结果 | 条件 |
|------|------|
| 大失败 | 骰值 >= 96 |
| 极难成功 | 骰值 <= 技能值/5 |
| 困难成功 | 骰值 <= 技能值/2 |
| 普通成功 | 骰值 <= 技能值 |
| 失败 | 其他 |

## AI 推荐行动

AI 响应中的 `playerChoices` 会显示为建议行动按钮。玩家可以点击写入行动输入框，也可以自由输入。系统会过滤刚刚执行过的建议，以及针对已发现、已穷尽作者物品的重复搜索建议；兜底建议优先给出不同职业方法、矛盾观察和未穷尽目标。

## 多玩家冲突

队伍回合中，若 AI DM 判断本轮玩家声明互相矛盾：

1. 首次冲突不结算不可逆后果，要求玩家重新输入本轮行动。
2. 重新输入后仍冲突时，AI 请求前端 `幸运` 检定进行仲裁。
3. 仲裁骰只决定本轮优先执行哪一方需求，后续行动权仍保留。
4. 对杀掉关键 NPC、破坏关键证物等不可逆行为，AI 应先确认并可用环境外力阻挡，避免主线死局。

## 状态更新

AI 不直接写 reducer。每轮固定执行：规则前置评估 → 玩家行动/检定 → Narrator → Director 工具审核 → 原子状态结算 → 自动目标/节点评估 → 时钟/后果推进 → 上下文与案件板更新。主线只接受 `propose_story_event(eventId)`；Director 校验事件属于活动节点且条件满足，效果只从 YAML 读取。重开、读档或返回首页会取消旧 session 的请求，防止旧结果污染当前游戏。
- activeNpc。
- playerChoices。

更新进入 reducer 后会进行归一化，避免非法值破坏游戏流程。

《雾中消逝》由 `scenarios/wuzhongxiaoshi/` 五个 YAML 文件维护，运行时、类型、KP 手册和案件板骨架均自动生成。场景移动同时受空间出口与剧情条件约束；必经节点连续 3 回合无进展时提示，6 回合时执行作者定义的失败推进。详见 [[scenario_engine]]。
