# 0.5.71 保存与重试接续

## 已确认的问题

手动保存原来只有一个全局忙标记。同一快照重复点击本应合并，但玩家修改行动后再次保存形成不同快照，也被静默丢弃。异步保存返回时还可能把上一局的成功或失败通知带到首页、新选角或刚读取的记录。保存失败虽然恢复了原生缓存，途中返回首页曾刷出的乐观存档列表却可能仍包含尚未落盘的记录。

API 设置原来先更新原生读取缓存，再等待写盘。写盘失败后，表单报告失败，但运行时仍读取失败的新配置；设备存储恢复后，后续生命周期 flush 还可能把它写到磁盘。

重试按钮在等待 DM 时卸载。如果本次仍失败，新按钮出现后没有恢复原先的键盘焦点；输入此时仍禁用，需要重新找回重试入口。这个候选准备时曾暂称未来 0.5.72，现合并到同一次 0.5.71 交付，没有单独发布 0.5.72。

## 最小修复

| 范围 | 最终行为 |
| --- | --- |
| 手动保存请求 | 只合并同一个仍在保存的 `GameState` 快照；不同快照继续进入原有串行持久化链路。 |
| 异步保存反馈 | 新保存请求及原有游戏会话切换使旧反馈失效；已接受的保存仍实际完成并更新存档库。 |
| 保存失败后的列表 | 在服务恢复缓存后重新读取存档库，让 UI、缓存和实际记录保持一致。 |
| API 保存失败 | 当前缓存仍为本次规范化写入时，恢复此前的原始配置值，或移除失败的首次覆盖；同时恢复原生 dirty 写入目标，并向原表单抛出原始失败。外部已写入的新值保持。 |
| 失败重试焦点 | 仅记录本次重试按钮原先是否拥有焦点；再次失败且焦点仍在 BODY、没有活动弹窗时，聚焦实际新按钮。菜单或其他输入接管则不抢焦点；成功、检定或设置修复均消费当次恢复意图。手机不聚焦行动输入、不强开键盘。 |

`useSaveSlots` 保留现有保存/删除接口，控制器只在已有 `cancelDiceRoll` 会话切换点使旧保存反馈失效。API 表单已有保存互斥、禁用及关闭保护，当前界面没有同时提交 B/C 两份原生配置的入口；本批沿用该边界。网页成功写入本机但开发服务不可达/404时仍按原软成功处理。

继续沿用原通知期限、自由行动、存档格式、COC 规则、剧情、美术、页面布局及原生队列；不增加设置、提示、队列框架或图像资源。

生产改动限定为 `useSaveSlots.ts`、`useGameController.ts`、`storage.ts` 与 `ActionDock.tsx` 四处。焦点修复只增加局部 refs 和结果提交后的布局检查，成功输入接续沿用已有策略；不改共享动效或 CSS。

允许在实际零引用复核后清理 `assets/avatars/deep_one.svg` 和 `assets/avatars/deep_ones.svg` 两份旧占位 SVG（合计 1300 字节）；它们不是美术原稿，也不在 17 项运行资源中。删除由主线交付负责人完成，本准备步骤没有删除资产。原图标与现有美术、资源审计继续保持。
