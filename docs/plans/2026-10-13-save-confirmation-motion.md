# 存档删除确认的自然高度过渡

## 目标与范围

修复手机存档列表点删除、再保留存档时确认区立即替换和卸载导致的卡片高度、后续记录位置突跳。仅调整 `SaveManagerModal.tsx`、`save-manager.css` 和移除 `motion.css` 的旧确认区固定起点淡入。美术、文案、删除二次确认、busy 单次执行、删除失败保留、读取及不兼容存档规则保持原样。

## 最小实现

- 每张记录常驻一个 `.save-slot-controls`，不使用子项 gap。提示区的边线、margin、padding 和文字全部置于现有 `DisclosureMotion` clip 内，使用既有自然高度与透明度双向过渡；收起后不留空洞。
- 44 px 操作行始终只包含当前一组按钮：正常时删除 / 载入，确认时保留 / 确认。逻辑切换即时生效，无旧确认按钮留在退出画面；`cancelRef` 只连接当前确认行。
- 取消后的提示可保留 DOM 与短暂画面，但立即 `inert` / `aria-hidden`，不再具有 status / alert 角色。现有即时聚焦保留按钮、返回原删除按钮和删除后相邻记录焦点恢复不变。
- 仅在自身提示区真实 `grid-template-rows` 过渡结束时，若弹窗仍逻辑打开、非 busy，且真实焦点仍位于当前记录可用按钮，复用既有 `focusInList` 校正可见范围。短窗末行最终展开后仍可触达；不抢其他记录或弹窗焦点，不等待动画才能操作，不使用永久逐帧循环。
- 快速反向复用同一提示 DOM 的原生 grid 过渡；减少动态沿用既有即时模式。移除确认区旧固定起点关键帧，避免重复淡入。浏览器回归发现后台规则只覆盖外层弹窗，补齐 `.ui-motion-paused .disclosure-motion` 的即时模式，让提示高度与已结束的视觉会话保持一致。

## 验收

1. 单人、双人、四人记录，手机竖屏、320 × 300 短窗和桌面；确认提示两向真实 RAF 存在中间高度，卡片高度与下一条记录 top 连续，完整收起无残留 padding / gap。
2. 快速删除 → 保留 → 删除时同一提示节点连续反向；每个时刻只有当前按钮组可交互，取消立即退出 AX，焦点立即回原删除按钮。
3. 短窗末行确认完成展开后，当前保留 / 确认按钮完整可见且点击可达；焦点移到其他行或关闭整个弹窗时，旧 transitionend 不移动焦点或滚动。
4. 原二次确认、busy 单次、取消 / 返回、失败保留及重试、载入、最后一份记录删除和不兼容记录均保持原行为；减少动态无额外等待。
5. 类型与差异格式检查后冻结生产源码，指定代理负责浏览器和 WebView 110 定向回归；不操作用户当前游戏或设备。
