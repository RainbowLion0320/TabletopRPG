# 0.4.5 自由行动容错与内部诊断隔离

## 问题与修正

用户截图显示同一轮反复出现“缺少 request_check”及“提前泄露未解锁地点”，玩家需要手动重试。没有取得同事设备的原始模型回复；本轮依据截图与运行时代码构造同类响应复现。

| 问题 | 修正 |
| --- | --- |
| 检定正则会把“不需要检定”等文案视为强制要求 | 区分否定、将来条件、过去描述与当前要求；明确当前要求但没有骰子入口仍要修正 |
| DM 明确要求某角色做某项检定，却漏了工具调用 | 对唯一行动角色/明确点名角色与已存在技能，补接 Director 审核后的 `request_check`；有歧义不猜测，已有工具、剧本检定与已结算骰果不重复补接 |
| 仅出现锁定地点名称就被当成新泄露 | 已接受 DM 正文中的名称可保持连续；玩家提出的猜测可以作为未证实信息回应。错误消息不算已知信息，猜测不解锁场景，真正的新隐藏线索与无工具切场仍受校验 |
| 本应是一般诊断的文本因包含“剧情事件”被升级为硬拦截 | 局部道具/痕迹、生活习惯等无作者事件诊断改为提醒；事件文案覆盖度按质量建议处理，不因缺少固定措辞卡死回合 |
| 最后一次自动恢复重新开始却丢失前次纠错原因 | 两次 Narrator 尝试耗尽后，将最后语义提示带入第三次恢复，保持同一行动、状态、骰果和超时预算 |
| 内部规则、工具名、隐藏地点被写入剧情且越积越多 | 格式/语义失败仅给通用说明；底部只保留一条恢复通知，重复错误替换，成功后清除。旧存档剧情/日志中的错误记录也不显示；网络与鉴权错误保留真实类别 |

保留已有主线、世界状态和数值规则；DM 可即兴处理局部环境、道具、人物反应与行动方法。补接检定不计算随机结果、不替玩家改行动、不直接更新状态或案件板。所有模型访问仍经 `src/dm/llm/client.ts`。
