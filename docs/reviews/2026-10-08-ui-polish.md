# 2026-10-08 持续 UI 与体验优化

目标：手机竖屏优先，沿用伦敦迷雾、旧黄铜与调查档案的现有风格，逐批处理控件美术、层次、阅读、操作和资源成本。每批验证后提交并推送 `main`，同步可安装 APK。玩法与叙事方向保持既有模组，重大取舍再与用户对齐。

## 第一批：调查员档案卡与主要按钮（0.4.7）

本轮实测截图来自当前源码的 390×844 / 320×568 浏览器，以及最终签名 APK 的 Android 15 专用 QA 实例；不把旧截图作为本轮证据。原图与日志在本机 `output/ui-2026-10-08/`，构建产物及测试证据不进入 Git。

| 步骤 | 审查发现 | 本批处理与状态 |
| --- | --- | --- |
| 1. 首页 | 开始与次操作同为深色细框，主要动作不够明确 | 绘制实心黄铜主按钮，文字/图标为深墨色；主次操作可区分，禁用与按下仍有反馈 |
| 2. 选择调查员 | 背景资料抢占空间，擅长技能藏在完整属性里；卡片伪按钮内嵌按钮，操作职责混杂 | 独立绘制档案底板；突出身份、两项擅长技能与四项核心资源，背景/完整属性/技能按需展开；真实 checkbox 与详情按钮互相独立 |
| 3. 进入单人/多人游戏 | 控件皮肤不能增加底部占用或遮住剧情与场景 | 主操作沿用已验证的尺寸，恢复队员/资料卡的统一细边；单人、双人、四人、骰子与恢复流程继续通过 |

细节：

- 默认亨利一人，可以替换或加选至四人；零人不能进入。
- 点击资料区或用空格选择；查看详情不更改选中队伍。
- 手机始终一行一人，600px 前后与宽竖屏不切双列；网页宽屏保留双列。
- 手机与网页统一固定队伍摘要/进入按钮，只有列表滚动。展开资料在正常布局中占位，不覆盖后续卡片。
- 移除选角在三个全局样式表中的重复布局规则，集中到 `character-setup.css`。
- 通用按钮 selector 改用 `:where`，修复默认纸色文字意外覆盖主操作颜色的问题。
- 两张 WebP 新增 100,454 字节，实测 APK 约增加 100KiB；九宫格保留护角，不把文字烘焙进图。
- 生成工具、完整提示词与转换步骤见 [材质说明](../../assets/ui/chrome/README.md)。

## 第三批：行动与剧情阅读（0.4.9）

用户确认手机采用多行输入、回车换行，按钮确认。实测旧输入框只有一行；剧情依赖消息总数强制滚动，会在回看时被新回复和内部记录打断。

- 行动框改为 textarea，空白 44px，手机上限 96px、桌面 104px，300px 键盘窗口 66px；超出后只滚动输入框。响应文字、折行宽度与窗口变化，清空后回收高度。
- 手机回车只换行，桌面保留回车确认与 Shift+Enter 换行，沿用中文输入法/长按保护。下一位保持输入焦点；多人卡显示行动中/已提交，结算时不显示宣言标记。属性入口仍保留当前角色和草稿。
- 阅读位置跟随最新可见记录开头；回看更早内容时暂停跟随，临时「新内容」入口返回最新回复开头。隐藏信息不触发滚动或提示；换一份存档重置到其最新记录。
- 草稿、换行与行动文本沿用现有存储和 AI 请求链路。测试凭据仅进入临时浏览器/专用安卓 QA，未改动任何玩家配置。

390px 四人实测截图 `11-four-actions-after.png` 与 `12-reading-new-content.png` 保存在本机验收目录。最终验证通过：605 项单元测试、生产构建、80 项浏览器流程；正式 APK 以原签名覆盖安装，8 组原生检查通过（94.793 秒），包括宽竖屏 textarea/回车行为、下一位接续输入、多行行动结算和加密草稿重启恢复。新增浏览器模拟延迟 DM 回复，验证旧阅读位置保留、最新长回复从开头显示及后续跟随。原有 AI 测试的提交定位改为精确名称，以区分队员卡中的“已提交”。最终包 `output/apk/Fog-TRPG-0.4.9.apk`，versionCode 14，SHA256 `893a1015af466e18122635f1035056d787da2bd90b98a1681b03dc1e9e4b3fbf`；包内实际脚本包含多行与新内容功能。

## 第四批：档案数值与默认 MiMo（0.4.10）

档案实测发现闪避显示 120/140%：旧公式将百分制 DEX 乘二。改为 `floor(DEX/2)`，四个预设分别为 30、35、32、50；巡警恢复原设定的 50%。旧存档只修正精确匹配错误基础的记录，保留额外投入与其他自定义值，重复载入不重复迁移。已发出的合法检定阈值保持原值，使锁定骰点的成功/失败不会因更新翻转；未来检定使用修正后的角色。回归覆盖四人、奇数敏捷、自定义数值、额外投入与 Android 锁定 80 点旧成功结果。

技能搜索切换队友时保留，便于比较同一技能；关闭重开恢复空查询。浏览器实际保存/载入旧测试局，巡警从 120 修正为 50，切换护士保留「闪避」并显示 35/17/7；截图 `14-investigator-skill-compare-after.png` 在本机验收目录。

用户于 2026-10-08 明确变更默认配置要求：APK 从系统 `APIKEY_MIMO` 注入 MiMo Token Plan / `mimo-v2.6-pro`。中国区官方 Base URL 经实际认证请求确认；已有玩家设置仍优先，首页/菜单可改，密钥继续遮蔽。构建脚本临时读取进程/用户/机器环境，资源构建后恢复进程原值。只提交注入逻辑；发布及原生测试构建缺少密钥时停止，开发预览与网页不接收该系统密钥。

实测接口返回 `responses_feature_not_supported`，MiMo 不接受 `json_schema`；有工具的 JSON-object 请求也未产出调用，而 text 模式与完整推理回传完成真实工具往返。适配器仅为 MiMo 使用工具阶段 text / JSON-only 阶段 json_object，指令中携带 schema，推理预留有限额度。Responses 保留原始 reasoning item；Chat 保留 reasoning content，私有推理不进入正文。模型先回提议而无正文时，只暂存并确认收到，获取一次 JSON 正文后再由 Director 审核，不提前落地或模拟骰果。OpenAI/custom 原有严格 schema 不改，既有结构/语义校验和有限恢复保留。来源：[官方 Token Plan](https://mimo.mi.com/docs/en-US/tokenplan/integration/codex-configuration)、[Responses 协议](https://mimo.mi.com/docs/en-US/api/chat/responses)、[JSON 模式](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/text-generation/structured-output)。

最终单元/生产构建/浏览器流程通过：617 项单元测试、81 项浏览器检查。正式 APK 已构建为 `output/apk/Fog-TRPG-0.4.10.apk`、versionCode 15、同原签名；SHA256 `a4bfa1fb22468288abe8b2f3a6d15c77fa870cb3ba16a776d6de22f18553f442`。只输出布尔结果的文件检查确认默认密钥/Pro 模型在 APK 中，真实密钥不在 Git 文件或网页产物。原生测试增加首次无配置启动、遮蔽及玩家连接重启优先检查；一般原生流程先改成独立 MockWebServer/测试凭据，保持离线。显式 `liveMiMo=true` 可在专用 QA 上执行一次实际首轮请求，普通测试不访问正式服务。

原生正式包最终 9 组离线检查全部通过（95.269 秒）；包内检查默认连接首装、遮蔽、手动配置重启优先和个人闪避、队友查询保留。显式开启真实服务探针后，默认配置完成一次实际首轮自由询问，单独原生检查通过（51.937 秒），玩家没有配置或点击重试。真实服务时延受模型和网络影响，该探针不代表完整剧本通关。专用 QA 安装信息为 0.4.10 / versionCode 15。首次测试的辅助配置函数错误地假定保存后菜单仍在；修正为按实际菜单状态收起，正式包复测通过。

## 后续优先级

1. 资料与档案的连续查看体验：核对手机技能搜索、页签、关闭返回和已知信息，减少重复操作。
2. 其余设置和弹窗：沿用固定返回/确认与独立正文滚动，持续核对焦点和目标尺寸。
3. 已知资料与案件板：便于查看证据、人物和关联，保留经过 reducer 审核的真实资料链路。
4. 存档、结局、过渡与资源成本：减少重复操作和不必要的界面跳动，兼顾音画与低端手机。
