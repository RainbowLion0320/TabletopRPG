## 修复结果

| 问题与触发 | 修复后的行为 |
| --- | --- |
| 单人正文“你的手没有受伤”、他人血迹、险些受伤，或包扎后“不再流血”被识别成新伤害 | 只识别明确的本人新损伤，保留真实受伤正例；否定、治愈、假设和他人痕迹不再默认扣血 |
| S01关窗时“玻璃掉落的威胁已解除”误触终幕剩余敌人数规则，反复重试 | 规则只约束相关场景的活动遭遇，并考虑本轮获准事件；普通局部危险可自然解决 |
| 模型先提出检定，再返回坏JSON，修复正文后检定被清空 | JSON修复保留待审工具及对应回执，最后共同审核；语义重做仍清除旧提议。覆盖Responses与Chat两种协议及工具／坏正文同包 |
| 作者战斗大失败已扣HP，DM复述伤势又被要求或默认扣一次 | 同一实际结算前后值生成本轮资源回执，随多人队列、重试及存档接续；复述不再触发默认二次扣款。显式新增伤害继续审核 |
| 小数HP/SAN被接受，保存后读档才截断，资源凭空改变 | 实际入库时向零截断为整数，读档保持同值；工具schema提示整数，有限旧格式继续兼容 |
| 安卓无配置时，进入离线引导／阅读存档／确认已锁定本地骰子先弹API设置 | 删除多余前置检查，实际需要模型时由原提交链路定位配置，行动与骰点保留 |
| 暂时保存失败后，最新记录已写入却一直显示失败；旧后台回调还可能带回失效提醒 | 最新写入或后台重试成功只撤销保存类提醒，读取受损提示独立保留；过期revision不更新当前反馈 |

本轮未增加模型调用、重试层、搜索筛选、玩家菜单或负向提示词层。资源回执只用于当前检定接续，缺少字段的旧v8存档保持原行为；真正的新伤害仍使用原有结构化工具。
