# 0.4.0 共享交互 UI 验收（2026-09-09）

## 目标与范围

根据用户“基础交互仍像普通网页”的反馈，结合现有骰子框、美术字体与伦敦调查故事完成一套生产 UI。手机竖屏优先，当前分支新版网页与 APK 共用主题和窄屏布局。原网页工作目录和 main 留存旧发布版。

沿用场景、NPC、骰子、音频和规则。AI 配置、存档格式、Native HTTP 与加密存储没有改动。

## 基线与修正

1. 首页：原有圆角普通按钮缺少与骰子框的关联。主操作使用黄铜铭牌，次操作用双线深框，保留真实图标与文字。
2. 配置与弹窗：统一皮革内区、细雕角、嵌入式输入槽与清晰内焦点；错误使用现有校验，关闭和保存保持常驻。
3. 选角：档案卡、四种属性色标、金色勾选章和选中底色；手机列表滚动，底部人数/进入按钮固定。
4. 游戏：建议改为档案标签、输入和状态条统一边框，菜单/资料/声音为图标工具；章节和场景文字提升对比度。
5. 资料与声音：页签用金色底线标识，卡片与人物资料同一框体；音乐/音效使用机械拨片和黄铜推子，关闭各自禁用滑杆。

实现中实际检查并修复两处叠层问题：通用按钮定位不能覆盖可拖动资料入口/详情关闭按钮的绝对定位；桌面新实色顶栏不能盖住 NPC，因此顶栏压为 64px，场景和立绘从其下方开始。手机仍使用既有的全宽场景画幅。

新增材质为 960×313 的黄铜边框和 128×128 的轻皮革纹理，共 56,520 字节。九宫格保留边角，文字实时渲染；来源、完整提示与打包脚本见 [资源记录](../../assets/ui/chrome/README.md)。控件、字体、颜色和工程入口见 [UI 规范](../UI_SYSTEM.md)。

## 验证证据

最终源码通过 `npm run check:full`：41 个文件 / 530 项单元测试、网页生产构建、60 项网页流程测试全部通过（流程测试 27.5 秒）。日志：`output/ui-check-final.log`。最终正式 APK 的 5 组原生测试全部通过（68.48 秒），日志：`output/ui-native-final.log`。截图、APK 和完整日志仅保存在忽略目录 `output/`。

- 浏览器逐页操作：标题、AI 配置、选角、游戏、菜单、声音、案件板与人物详情。音乐独立关闭时其滑杆禁用，音效仍可操作；之后恢复音乐。
- 四人竖屏探针：320×568、360×640、390×844、412×915、430×932、600×960。无页面横向溢出，场景完整、控件在界内，320×568 保留约 148px 滚动剧情区。结果在 `output/ui-redesign/phone-matrix.json`。
- 新版网页：390×844 / 1440×900 切换保持两人队伍及输入草稿；检查标题、场景/顶栏边界、输入聚焦和桌面菜单。
- 包内验证：使用独立 MuMu QA 实例，安装正式签名 APK，保留原签名升级；覆盖 1/2/4 人、长弹窗、实际 WebView 输入、300px 剩余视口、资料返回层级、API 协议、音频、加密恢复及骰点恢复。

手机键盘检查包含 Android 调整视口后的布局边界，但模拟器只提供零高度虚拟输入法，不能等同于所有真机输入法验收。文字对比度断言针对章节及场景文字，不宣称整个游戏已完成无障碍认证。
