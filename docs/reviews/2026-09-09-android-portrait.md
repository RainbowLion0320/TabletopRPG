# Android 0.3.0 竖屏重构验收

用户将手机端方向调整为竖屏，要求整个操作与 UI 相应重排。当前实现以竖屏为默认，原网页目录 `G:\TabletopRPG` 及 `main` 保持在 `118cf49`；改动位于独立 Android 工程和 `codex/android-apk`。

## 最终界面

- 原生 Activity 请求竖屏，继续使用键盘缩小窗口；不依赖页面旋转或整体缩放。
- 主界面为上方 NPC 独立展示、中部滚动剧情、底部行动。立绘保持比例并淡出底边，不被正常阅读面板覆盖；无 NPC 时回收展示空间，展开阅读时扩大正文。
- 正文为 15px；主要输入/提交触控高度至少 44px。建议可横向滑动，收起 Android 的粗滚动条；多人状态两列排列，四人全部可见。
- 选角为纵向卡片列表，已选人数和进入游戏按钮固定在底部；默认一人，零人时按钮禁用，完整属性在卡片内展开。
- API 表单与声音设置纵向排列，人物详情上图下文，案件板为竖向卡片和独立详情页，存档操作排列在卡片下方。长内容内部滚动，关闭/保存固定。
- 骰子保留原美术、字体和结果逻辑，采用顶部检定信息、中部美术、底部确认的排列。
- 使用宽度及可用高度作为断点，避免键盘缩短视口后误用横屏布局；500px 及以下隐藏 NPC，300px 及以下进一步回收辅助信息，保留输入、提交及设置保存。

### 输入法验证边界

本轮额外尝试真实软键盘。MuMu 自带 Sogou 虚拟输入法报告打开，但窗口 IME 区域为 `[0,1688][780,1688]`，实际高度为 0。临时安装官方 [HeliBoard 4.1](https://github.com/HeliBorg/HeliBoard/releases/tag/v4.1) 后，系统键盘列表仍只开放 MuMu 的虚拟输入法，标准启用命令也被模拟器禁用；未绕过系统限制，验证后已卸载该辅助键盘。

因此，已验证的是 APK 内 300px 剩余视口、焦点输入/提交/保存及返回行为，不能视为覆盖所有真机输入法。目标手机上的真实键盘和厂商安全区仍需实机验收。最终竖屏全尺寸截图为 `output/portrait-native/final-game.png` 与 `final-setup.png`。
