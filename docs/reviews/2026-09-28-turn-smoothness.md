# 0.4.6 回合流畅性与缺陷修复

本轮把审查中复现的四处缺陷修复，并清理会打断玩家的非必要重试和内部信息。保持原剧本、角色、数值、主线规则与手机竖屏布局。

## 修复

| 已复现的问题 | 结果 |
| --- | --- |
| Narrator 的玩家建议及 System2 心智模型使用开放对象，却以严格结构化输出请求模型 | 按当前玩家/NPC 名单声明封闭对象，所有键进入 required；可选心智值用 null。两种协议共用相同业务契约，保存格式不变 |
| “检定没有通过 / 未能成功 / 并未成功”被当成失败改成功 | 对检定的明确结果断言识别否定，优先匹配结构化骰果的玩家与技能，兼容旧文本和多人混合结果 |
| “需要注意，这里无需检定”“请不要检定”“先征求同意，之后再检定”意外触发掷骰 | 请求动词与检定限定在同一分句，识别局部否定与将来条件；不为这些说明生成骰子 |
| 多人要求多项检定但只返回第一项工具，后续角色被漏掉 | 按玩家/技能补接缺失项，保留已有工具的难度；Director 继续审核，已确认结果与剧本检定不重复 |
| 质量建议会额外生成一次，玩家等待变长 | advisory / warning 直接接受，仅保留开发诊断；权威状态冲突仍有限重试，纠错只针对当前冲突 |
| KP 笔记、配置错误、服务原始错误混入玩家界面 | KP 笔记移至开发调试抽屉；配置错误留在设置弹窗；接口错误映射成固定操作提示，旧存档错误也脱敏 |
| 多人骰果只有“成功/失败”，日志还重复骰点 | 剧情及日志统一“调查员 · 技能：结果（骰点）”，每次骰果只追加一次 |

严格结构化输出的对象约束依据 [OpenAI Structured Outputs 文档](https://developers.openai.com/api/docs/guides/structured-outputs)。修复不通过堆叠新的负向提示词或扩大拦截名单实现；自由环境、局部道具、人物反应和未证实猜测维持原有发挥空间。

## 验证

- `npm run check:full`：48 个文件、593 项单元测试，网页生产构建及 70 项浏览器流程全部通过。
- 生产 schema 测试捕获 Narrator、摘要、事实抽取、System2、案件板五个实际业务请求；对 Responses / Chat Completions 和 1/2/4 人名单检查严格对象规则及响应形状。
- 新增完整管线用例复现否定、将来、失败骰果和部分多人工具；正常响应仅生成一次。真实改写骰果、隐藏主线、丢失检定入口仍会被规则识别。
- 浏览器在 390×844 走完四人声明、四次骰子确认和 AI 续写，只有两次必要的 Narrator 请求，声明及骰果均无重复，行动区恢复可用；菜单无 KP 笔记。
- 最终正式 APK 覆盖安装至专用 Android 15 MuMu QA 实例（VM 2），同签名测试 runner 对 release 包执行完整回归：`OK (8 tests)`，87.871 秒。
- 原生回归包括 1/2/4 人、四档竖屏与宽手机选角、人物档案、案件板、API 设置、加密恢复、锁定骰点、系统返回、原生取消、声音开关，以及新增“无需检定 → 四人部分工具 → 四个失败骰果正常续写”流程。
- 已检查正式包的多人结果与失败恢复截图，操作控件可达，页面不显示工具名或未解锁地点。截图黑边是 QA 模拟不同 CSS 视口留下的画布。

接口回归使用可重复的模拟响应与本地 MockWebServer；没有调用玩家的收费 API，也不把它当作同事原设备或真实模型长局的验证结论。
