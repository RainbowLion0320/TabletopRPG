## 已修复的问题

| 范围 | 原问题与玩家影响 | 修复 |
| --- | --- | --- |
| 行动提交 | 缺少有效配置时可能先清空行动；同一次渲染内重复提交可能重复发起请求 | 提交前检查配置，用同步任务引用防止重复提交 |
| 失败恢复 | AI 请求失败后缺少明确的原回合恢复入口；格式重试叠加浪费请求 | 保留 `pendingDmActions`，提供“重试本轮”；自动恢复最多三次普通 Narrator 尝试 |
| 存档续跑 | 保存正在请求的回合后，读档可能失去原声明或确认骰果 | 保存原行动及结构化骰果，载入后原轮续跑，浏览器测试验证无重复声明 |
| 异步取消 | 超时旧会话可能污染新游戏；忽略 AbortSignal 的后台 Promise 可阻塞整个更新队列 | 会话代数校验与可中止等待，过期结果不可写回 |
| 上下文 | 本轮行动同时出现在历史与当前动作中；骰后续写、后台事件回合可能偏移 | 提交历史与请求状态对齐，当前动作只进入提示词一次，统一正式回合号 |
| 混合检定 | 一人失败可阻断另一人的成功线索，正确的混合成败叙事被误判 | 按玩家、技能及目标线索匹配本地骰果，兼容旧文本骰果；仍拒绝明确改写结果 |
| 数值检定 | SAN、属性名、不同括号写法可能落到未知技能默认值 25 | SAN 读取当前理智，属性读取实际值，规范化技能空格/括号，检定人同步实际计算对象 |
| 连续检定 | 作者事件追加聆听/说服等检定时可能丢失之前的声明与骰果 | 新检定继承原行动和已完成结果；结局不恢复残留检定 |
| 回合后果 | 检定前奏和最终回复都可能消耗后果/意图寿命 | 前奏不提前衰减或启动认知，最终结算推进一次 |
| 长局记忆 | 重叠后台摘要只按长度落地，可能覆盖新摘要/历史；压缩后正式回合倒退 | 核对源历史前缀，保留后续消息，累计 `summarizedTurnCount` |
| 已知资料 | 历史裁剪后可能忘记访问过的场景；后台案件板遗漏作者事件刚解锁的线索 | 从权威推进状态恢复访问记录，并投影本轮已解锁线索与 flags |
| 结局奖励 | React 重算或骰后预计算会再次抽取随机奖励 | 每个 action 只生成一次随机种子，重复计算保留相同数值结果 |
| 存档健壮性 | 同毫秒存档可能覆盖；非法时间 ID 会导致异常；存储失败缺少反馈 | 递增 ID、校验时间范围、处理写入/删除失败；未确认骰果期间阻止存档 |
| AI 配置 | 非字符串字段可能崩溃；env 写入破坏注释/引号；跨站或换行输入缺少保护；保存配置触发刷新丢局 | 规范化与 URL 校验、同源 JSON/体积限制、保留无关配置、env 写入不刷新当前局、明确浏览器保存结果 |
| 模型响应 | HTTP 成功但返回 null/数组等可触发无意义的 TypeError | 转成可恢复的格式异常 |
| 输入与键盘 | 中文输入法 Enter、长按 Enter 可意外提交；资料按钮键盘无法打开；弹窗焦点可落回游戏输入 | 防误提交、资料支持键盘，设置/资料/存档/详情/KP 笔记管理焦点与 Escape |
| 启动性能 | 标题每次加载约 50.45 MB GIF，关闭的资料面板也加载案件板 | 同一动画转为 458,103 字节 WebM（减少约 99.1%）；不可见/减少动态效果时暂停；案件板按打开状态加载 |
| 入口与文档 | 开局建议没有明确接受委托；文档混用存档 v2/v8、4/5/6 个 NPC 和旧记忆时序 | 首位调查员提供作者定义的接受委托建议；同步 PRD、SPEC、GDD、源码说明与 Wiki |
