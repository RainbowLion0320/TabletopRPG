## 自动保存与检定连续性（0.5.1）

0.5.1 将安卓连续行动输入的自动保存合并到最长 250ms 的有界窗口，内存续玩立即使用最新草稿；提交、换人、手动存档、返回首页、重新选角、切到后台、页面离开和退出立即保存最新内容。完整历史、多人草稿和锁定骰点保留，存储格式与加密方式不变。强制杀进程且未收到生命周期通知时，最多一个尚未写入的输入窗口可能无法恢复；不把异步保存描述成绝对零丢失。骰子揭晓沿用已加载的静态骰面，避免替换图片时短暂空白，原计时和确认逻辑不变。

### 3.2 技能检定系统

**检定流程**
```
AI DM判断触发技能
    ↓
掷 D100
    ↓
```

### 3.4 战斗系统

> 当前 MVP 尚未自动化完整战斗轮序和伤害系统；本节为后续实现目标。当前遇到战斗时，由 AI DM 请求前端检定并按结果叙事，角色退场按 7.8 的默认保护规则处理。

**回合流程**
```
1. 宣言阶段：所有人宣布行动意图
2. 行动顺序：DEX从高到低
3. 执行阶段：逐个执行（AI裁判）
4. 结算阶段：HP/SAN变化，状态更新
```

**攻击判定**
```
玩家输入攻击描述
    ↓
AI DM解析：
  ① 合理性：是否持有武器/具备能力？
  ② 创意行动：非常规攻击如何处理？
  ③ 优劣势：当前情境给予优/劣势？
    ↓
武器技能骰检定
    ↓
命中→伤害骰+DB
未命中→叙述失败情景
```

**濒死与死亡**
- HP ≤ 0：濒死，每轮失去1HP，需急救
- 完整规则目标：HP 降至负值等于最大 HP 时当场死亡；当前 MVP 先按 7.8 处理为软退场/救援机会
- 重伤（单次≥最大HP/2）：体格检定失败→昏迷

当前实现中，【资料】是全屏“混合调查台”，辅助页签只保留“日志”。案件板主图只放玩家已知的人物、地点、物证、关键事件和核心推测；NPC 目标、态度、证词、知识和状态变化进入对应实体档案时间线，不再逐条堆成卡片。静态主线骨架保证关键关系稳定，AI 只提议无法确定性生成的关键事件、跨实体关系和至少连接两个锚点的推测，所有 patch 仍经过来源、去重、反剧透和容量审核。

桌面端按当前可见关系自动形成“调查脉络”，按需加载 ELK Layered 和 React Flow，提供平移、缩放、适配、搜索、类型筛选和推测开关；选择节点后在右侧档案栏查看关系、实体时间线和“第 N 回合：事实原文”式来源。移动端不构建关系画布或布局 worker，改为按调查脉络分组的照片档案列表，每张卡最多显示两条关系并使用全屏详情；单资料分组不重复显示标题。AI 不生成坐标，后台新增资料不会重置玩家当前视口。摘要只统计已显示且非零的资料，不包含任何未解锁主线暗示。

叙事区采用安全的混合富文本层：人物、地点、物证、技能、检定结果和关键状态由前端剧本词典确定性识别，人物按规范化姓名获得全局稳定颜色；Narrator 只可补充本轮自由叙事中最多 6 个 `clue` / `danger` / `state` 原文短语。模型不输出 HTML、Markdown、颜色或坐标，所有标记由 React 按纯文本区间渲染。点击标记打开统一资料弹窗，未正式获得的实体只显示公开描述，已解锁信息可显示，但永不提示仍有多少条秘密。

## 六、多人系统设计

### 6.1 MVP阶段：本地同屏多人

**实现方式**
- 同一浏览器/同一屏幕，本地 hot-seat 体验。
- 当前可选 1-4 名预设调查员。
- 所有调查员始终处于同一场景；前端按座位顺序逐人收集本轮行动，AI 一次性结算完整队伍回合。
- 任一调查员触发合法场景移动时，全队同步进入新场景，不存在逐人选择场景或单人结算入口。
- 多玩家冲突按 7.6 执行：首次重输，本轮仍冲突则使用 `幸运` 检定仲裁。

**探索阶段轮序**
- `currentActorIndex` 仅控制当前显示哪名调查员的行动输入框。
- 每名调查员完成声明后进入下一位；最后一位提交时组合为“本轮行动宣言”。
- `currentScene` 是全队唯一的位置事实，场景图、章节、在场 NPC 与 AI 上下文均从它同步派生。

**战斗阶段轮序（设计目标，当前 MVP 未自动化）**
- 完整战斗轮序后续按角色 DEX 值从高到低执行。
- AI DM 控制 NPC/怪物轮次。
- 显示倒计时提示（扶桑花号6-7轮逃脱）。

**本地数据结构（当前实现）**
```typescript
GameState {
  players: Investigator[];      // 当前 MVP：1-4 名预设调查员
  currentActorIndex: number;
  currentScene: SceneId;        // 全队共享的唯一位置
  declarations: Record<string, string>;
  flags: Record<string, unknown>;
}
```

| 规则仲裁 | COC规则正确执行，确保平衡 |

### 7.2 Prompt架构设计

```
System Prompt（固定层）
├── COC第7版规则摘要
├── 《雾中消逝》剧本完整数据（场景/NPC/线索/触发条件）
├── 当前场景状态（地点/NPC/可交互物品）
├── 所有玩家角色卡（属性/技能/HP/SAN）
├── 剧情标记状态（flags）
├── AI DM行为准则（防注入规则）
└── 输出格式规范

User Turn（每轮）
└── [玩家名] 的行动：{玩家输入}

AI DM输出结构（JSON）
{
  "narrative": "场景叙述文本（给玩家看的）",
  "activeNpc": "当前交互 NPC 全名或 null",
  "nextPrompt": "接下来你们想做什么？",
  "playerChoices": {
    "亨利·格雷": ["仅适合亨利的建议1", "建议2"],
    "艾达·华莱士": ["仅适合艾达的建议1", "建议2"]
  },
  "keywords": [{ "text": "水里的东西", "kind": "clue" }]
}
```

检定、状态更新、场景变化和内幕解锁不写入 Narrator JSON，而是通过工具调用提议；Director 校验后才由 StateResolver 转为游戏事件和 reducer 可消费状态。

运行时格式规则：

- 剧情事件摘要只供 DM 续写参考，不额外插入玩家对话；内部事件编号不出现在玩家日志。当前页面及旧存档中的同类系统摘要也隐藏，保留正常叙事、检定结果、实际 HP/SAN 变化、结局和错误提示。DM 从已结算事件上下文读取最近六项事件的叙事锚点。
- AI DM 输出必须能解析为符合上述契约的 JSON 对象。
- `keywords` 为兼容旧模型的可选增强字段；非法或不在 narrative 原文中的标记静默丢弃，不触发重试，也不影响叙事正文。
- 完整 Markdown JSON 代码块可以被提取解析，但 system prompt 要求模型不要返回代码块。
- 第一次输出语法无效时，前端先用本地确定性 JSON repair 修复，并重新验证完整 Narrator 字段；截断或缺字段内容不能直接展示。
- 本地无法修复时，前端才向同一 Provider 发送一次格式修复请求；重试结果再次经过严格解析和本地修复。
- 修复重试后仍无效时，控制器再尝试一次完整生成（普通 Narrator 请求累计最多三次）；仍失败只在操作区显示一条简洁说明与“重试本轮”，保留原声明和已确认骰果，允许存档后续跑。内部诊断、接口原文、坏 JSON、Markdown 或混合文本不会作为 DM 叙事展示。
- 网络连接中断、认证失败、权限不足、限流和服务异常按真实原因提示，保留 HTTP 状态（如有），不进入格式修复或关闭工具能力；本轮声明和确认骰果继续保留，恢复后可手动重试。取消请求保留原取消原因。
- Narrator 完成后立即展示叙事；总结、事实、NPC 心智、情景记忆和动态案件板在后台继续，按回合顺序落地。
- 重开、读档、返回首页、超时或卸载会取消旧请求，旧会话结果不得写入当前游戏。

### 7.3 自由度边界控制（核心设计）

系统采用“硬主线、软过程”的三层事实模型：

**Layer 1：权威状态（硬边界）**
- 前端骰果、HP/SAN/物品、当前场景、正式线索、剧情变量、遭遇人数和结局不可由自由文本改写。
- 主线事件、状态变化和切场必须经工具提议、Director 审核与 reducer 落地。
- 物理现实、角色实际能力/资源、内容安全和 prompt 注入仍是明确边界。

**Layer 2：连续性事实（AI 可即兴）**
- AI 可创造不会直接解锁主线的临时环境、无名路人、NPC 即时反应、含糊传闻、局部障碍、机会和代价。
- 这些内容可以影响玩家之后的做法并保持连续，但不能升级为正式线索、确定人物关系、隐藏地点或结局条件。
- 一轮可包含多项独立检定，不设置固定的一轮一次行动或一次检定上限。

**Layer 3：氛围细节（自由发挥）**
- 感官、节奏、动作、对话措辞和场面调度由 AI DM 自由主持。
- 非常规行动与剧情外行为先让其发生，再由检定、代价、NPC 反应和环境后果自然塑造方向。

生产管线对语义问题分级处理：权威冲突有限重试，质量建议与普通风格偏差直接放行并仅保留开发诊断，不为文风另起生成。前端不再用固定模板替换 AI DM 的整段回复。

### 7.4 AI DM容错度（已决策）

AI DM 容错度用于衡量：当玩家提出非常规、非预设、绕路或高风险行动时，AI 是直接拒绝、要求检定、给出代价，还是允许剧情大幅改写。

| 等级 | 含义 | AI DM处理 |
|------|------|-----------|
| 0 | 禁止 | 违反世界观、破坏游戏结构、prompt注入或越过安全边界时直接拒绝 |
| 1 | 严格 | 只允许剧本明确支持的行动，非预设行动多半拉回 |
| 2 | 保守 | 允许合理行动，但优先把结果导回主线 |
| 3 | 宽容 | 允许创造性解法，只要逻辑成立就给检定、代价和后果 |
| 4 | 高自由 | 玩家可以大幅改变路线，AI 动态改写剧情结构 |
| 5 | 沙盒 | 剧本仅作为背景，几乎完全开放 |

**MVP采用 2.5-3 档：宽容玩家的做法，不宽容破坏世界逻辑和主线闭环。**

执行规则：
- 合理但非预设的行动：允许尝试，给出对应技能检定、难度和叙事后果。
- 创意解法：只要符合 1920 年伦敦、COC 规则和当前持有资源，应优先转化为检定，而不是直接否定。
- 高风险行动：允许，但必须给出清晰代价，例如警觉、受伤、SAN损失、线索损坏、NPC关系恶化或时间推进。
- 离开主线的行动：可以短暂响应，但通过新信息、NPC反应或环境压力把玩家自然引回调查。
- 破坏性行动：不让游戏卡死；如果玩家烧毁、绑架、逃离或攻击关键对象，AI 要保留替代线索或后果路径。
- 绝对拒绝：违反物理现实、角色能力、内容安全、prompt注入、要求泄露系统设定、让骰子结果失效等行为。

典型例子：
- “冒充警察套话” → 允许，要求话术/信誉/法律检定，失败会提高警方警觉。
- “拿鸦片样品试探药店老板” → 允许，要求心理学/话术/侦查检定，可能提前触发危险。
- “绑架蒙特利尔审问” → 高风险允许尝试，但触发法律后果、暴徒反扑或关键 NPC 敌对。
- “烧掉卡森其药店” → 允许造成后果，但核心线索需要以烧剩残片、目击者或港口线索替代，不直接死局。
- “不查案直接离开伦敦” → 可以叙事短暂结果，但通过委托人求助、新闻、警方介入或失踪者危机引回主线。

### 7.5 骰子权威性（已决策）

**决策：AI 不可以在任何情况下无视、推翻或改写前端骰子结果。**

骰子是规则的一部分，不是叙事建议。AI DM 可以提出是否需要检定，也可以在检定结果出来后解释叙事后果，但不能为了剧情需要把成功说成失败，或把失败说成成功。

| 环节 | 权威归属 | 说明 |
|------|----------|------|
| 是否需要检定 | AI DM 提议 | AI 根据行动风险提出技能、难度、玩家和原因 |
| 技能值与阈值 | 前端规则系统 | 由角色技能和难度计算 |
| 掷骰结果 | 前端规则系统 | D100 结果是事实，AI 不得重掷或改写 |
| 结果解释 | AI DM | 只能在骰子等级范围内叙事 |

执行规则：
- 成功不能叙述成失败；失败不能叙述成成功；大失败必须体现明显负面后果。
- AI 可以区分“成功但有代价”“失败但剧情继续”，但不能改变本次行动的成败事实。
- 如果主线需要继续，失败时应使用替代线索、额外代价、新 NPC 反应或后续机会推进，而不是无视失败结果。
- 极端情况也不能无视骰子；只能触发新的独立检定、引入后果路径，或让玩家用新行动补救。
- 玩家要求 AI 直接改骰、重掷、宣布成功或忽略大失败时，AI 必须拒绝或重申规则边界。

### 7.6 多玩家冲突处理（已决策）

多人同屏行动时，玩家之间可能出现目标、顺序或后果互相冲突的声明。AI DM 负责判断本轮行动是否存在实质矛盾。

**决策：先给玩家一次重新输入本轮行动的机会；若仍然矛盾，则用前端骰子判定按谁的需求执行。**

处理流程：
1. AI DM 判断本轮声明是否冲突。
2. 如果是首次冲突，AI 不结算本轮不可逆后果，提示玩家“本轮行动存在矛盾，请重新输入一次本轮行动”。
3. 玩家重新输入后，如果需求仍然矛盾，AI 提出一次前端骰子仲裁。
4. 骰子仲裁结果决定本轮优先执行哪一方需求，AI 按骰子结果叙事。
5. 仲裁后仍要遵守骰子权威性：AI 不能无视或改写仲裁骰结果。

MVP 执行方式：
- 冲突仲裁使用前端 D100，优先请求 `幸运` 检定。
- 两名玩家冲突时，AI 指定其中一名玩家进行 `幸运` 检定：成功则该玩家需求优先，失败则对方需求优先。
- 多名玩家冲突时，AI 先聚焦最直接、最紧迫的一组冲突；复杂情况可拆成多次仲裁。
- 仲裁只决定“本轮优先执行谁的需求”，不代表被否决玩家永久失去后续行动权。

严重影响剧情的不可逆行为需要额外保护：
- 例如杀掉关键 NPC、破坏关键证物、烧毁关键地点、让主线信息永久消失。
- AI DM 一般应先通过表达阻止：反复确认玩家是否真的要这样做，并明确说明可能后果。
- 如果行为仍会破坏主线闭环，AI 可以让环境中的外力进行阻挡，例如 NPC 逃离、他人制止、证物被提前转移、门锁/浓雾/警察/暴徒介入。
- 阻挡应以叙事后果呈现，不应粗暴说“系统不允许”；但也不能为了自由度让游戏进入死局。

### 7.8 剩余规则边界（默认方案）

**剧情硬节点**
- 必触发：S04 的深潜者出逃与浓雾咒术，并给出 I07 地图笔记的明确调查机会；I07 仍须实际检定并失败推进，S05 负责终幕结算。
- 可绕路但不可永久跳过：S03 老赫特、S02 警察局都可以作为信息源或压力源，玩家不去时由替代线索、NPC 反应或时间压力补足。
- 不直接封死主线：关键线索被破坏时，AI DM 通过残片、目击者、NPC 转述、港口痕迹或后续检定提供替代路径。

**角色死亡 / 失控处理**
- 当前 MVP 不主动制造永久退场，HP≤0 先进入濒死，允许队友急救、NPC 干预或剧情代价换取继续参与。
- SAN≤0 先进入短期失控或恐惧反应，由 AI DM 描述失控行为和代价；完整长期疯狂表进入 backlog。
- 如果玩家坚持高风险行为导致角色不可逆退场，AI DM 应明确后果、二次确认，并允许该玩家以旁观、临时 NPC 或后续替补角色继续参与。

**AI 记忆长度**
- 当前实现通过 `conversationHistory` 保留近期对话，通过 `flags`、`clues`、全队唯一的 `currentScene` 和行动日志保留结构化状态。
- 当上下文过长时，AI DM 优先依赖结构化状态，不把长篇自然语言回忆作为唯一事实来源。
- 后续需要增加摘要压缩时，摘要只能记录已发生事实、线索、NPC态度和未解决问题，不应改写骰子结果或剧情标记。

**《雾中消逝》特殊处理**
- 蒙特利尔的语言类技能默认失败不应明说成“系统免疫”，而应表现为态度强硬、话术被识破、回答避重就轻；心理学可降为困难难度。
- 深潜者露脸 SAN check 在玩家首次清楚目击深潜者、浓雾咒术或非人特征时触发；模糊声音、传闻和间接痕迹不强制触发。
- 扶桑花号倒计时从 S05 明确进入追逐/战斗后开始计数，以“轮”为单位；交涉路线不使用 6-7 轮逃脱倒计时，但可以用雾、船员催促和敌方警觉制造压力。
